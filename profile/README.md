<p>这篇把购买双ISP住宅IP时要看的参数拆成可打分的几项，说明每项为什么重要、怎么问、怎么验，再讲配置和预算怎么按业务量分配，最后给一套下单前的核对顺序。</p>
<h2>一、先把需求写成一句话</h2>
<p>比如三个店铺、每天在线八小时、要固定地址，写成一句再问价，几家的报价才有可比性。</p>
<p>需求写不清，最后一定被销售牵着走，买回来的配置不是不够就是过剩。</p>
<p>写需求时把设备数、地址数、带宽、租期四个数字定下来，其余都可以后调。</p>
<h2>二、地址来源是第一顺位</h2>
<p>先看地址登记在哪个运营商、属于哪个城市，再看是不是独享，顺序不要颠倒。</p>
<p>双ISP的关键是两条出口来自不同上游，同一家运营商的两个地址， redundancy 意义有限。</p>
<p>地址能不能续用也要问，有的套餐换周期就换地址，业务刚养熟就断，损失比月费大。</p>
<h3>核验比听介绍可靠</h3>
<p>拿到测试地址查一次归属和ASN，两分钟就能确认对方的说法，比看十页产品页有用。</p>
<h2>三、带宽和并发的真实关系</h2>
<p>带宽决定同时能跑多少路，并发连接数决定能开多少窗口，两个指标要一起问。</p>
<p>只标带宽不标并发，多半是共享出口，人多时连接排队，页面会一直转圈。</p>
<p>上行带宽常被忽略，做上传、直播、云盘同步的业务，上行不够会直接卡住流程。</p>

<h2>四、配置按业务量配</h2>
<p>两核两G是入门线，只跑浏览器和后台够用，多开窗口建议四核四G。</p>
<p>内存比CPU更容易成为瓶颈，开十几个标签页再挂同步工具，四G内存很快见底。</p>
<p>硬盘看用途，只做操作三十二G够，要存素材和日志，一百G以上更省心。</p>
<h3>内存先加满再谈CPU</h3>
<p>多开窗口时内存吃紧会先出现卡顿，此时CPU占用往往不高，加内存的收益比换CPU直接。</p>
<h2>五、价格怎么比才公平</h2>
<p>比价要按同一口径：同样地址数、同样带宽、同样租期，再比总价，否则没有意义。</p>
<p>把一次性费用单列出来，初装、调试、换地址都可能是额外项，摊到月费里才看得清。</p>
<p>价格区间只能参考，同一配置在不同城市能差三成，热门地区溢价很常见。</p>

<h3>比价要留出余量</h3>
<p>预算按报价上浮两成准备，换地址、超量带宽、临时加机器都可能产生额外支出。</p>
<h2>六、下单前的核对顺序</h2>
<p>先验地址，再压带宽，再跑一天稳定性，最后才付款，这个顺序能挡掉大部分坑。</p>
<p>付款方式优先选可退的，预付三个月比年付安全，试错成本低很多。</p>
<p>把销售承诺的每一条截图存档，出问题时这是唯一能拿出来的依据。</p>
<p>交付后先自己复测一遍再开工，服务商自带的测试报告只能当参考，不能当结论。</p>
<h2>常见问答</h2>
<h3>双ISP住宅IP一定要买独享地址吗？</h3>
<p>答：做多账号隔离建议独享，一个账号一个出口是底线。只做浏览和采集，共享地址成本低，但要接受同段他人行为带来的不确定性。</p>
<h3>配置买高了会浪费吗？</h3>
<p>答：会。双ISP场景的瓶颈通常在带宽和地址质量，不在CPU。把预算优先给带宽和独享地址，主机配置按实际开窗数配就够。</p>
<h3>价格低的套餐能不能长期用？</h3>
<p>答：短期可以，长期要看两点：地址是否会被回收、带宽高峰是否掉速。这两项在低价套餐里波动较大，建议先按月观察。</p>
<h3>同一服务商加地址比换一家便宜吗？</h3>
<p>答：通常便宜，省了初装和调试。但如果是为了双ISP冗余，同商加地址拿不到第二家运营商，冗余目的就落空了。</p>
